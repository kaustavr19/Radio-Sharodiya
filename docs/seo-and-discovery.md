# Search and social discovery

This records the technical foundation for search and social-share discovery, and what still depends on a decision rather than code.

## What's in place

- **Canonical URL** (`https://radio-sharodiya.in/`) declared in `index.html`, so search engines treat it as the single authoritative address regardless of how the link is reached.
- **Open Graph and Twitter Card** meta tags give a real title, description, and a purpose-built 1200×630 share image (`public/assets/social/og-image.jpg`) when the link is pasted into WhatsApp, Facebook, Twitter, or similar — instead of a bare URL.
- **JSON-LD structured data** (`WebSite` + `Organization`) identifies the station as a named entity to search engines. Deliberately not `RadioStation` schema — this is a curated on-demand experience, not a broadcast frequency, and the closer-fitting schema types are safer than one that doesn't quite match reality.
- **`robots.txt`** allows crawling of the public site, explicitly excludes `/beta-admin` and `/api/*` (already `noindex`'d via response headers in `vercel.json`), and points to the sitemap.
- **`sitemap.xml`** — a single entry, since this is a one-page application with no distinct routable URLs.
- Exactly one `<h1>` in the raw HTML: the station's own headline (`#hero-title`), not the beta gate's. The gate's heading is an `<h2>` — a real page-independent identity should own the one `<h1>`, not a temporary interstitial.

The share-preview image is generated by `scripts/generate-og-image.mjs` (requires `npm install --no-save sharp`, matching the pattern in `scripts/generate-app-icons.mjs`) — re-run it and commit the result if the brand mark or the featured background scene changes.

## What still depends on a decision, not code

- **The beta gate is live in production right now.** The current title/description/OG image describe the full station experience (not "request an invite"), by deliberate choice — the intent is for the waitlist page itself to be discoverable and shareable ahead of launch, not hidden behind `noindex`. If that changes, the meta tags don't need to: they were written to be evergreen across both the gated and open states.
- **Submitting the sitemap to Google Search Console / Bing Webmaster Tools** is a one-time manual step outside this repository, needed once the domain is live, to get the site crawled promptly rather than waiting for organic discovery.
- **Rendering**: the app is fully client-rendered (no SSR/prerendering). Googlebot's evergreen renderer executes JavaScript and the real content appears immediately once script runs (there is no async network wait to unlock the application when the gate is off), so this was judged adequate for now. It's the one structural limitation worth revisiting if indexing coverage in Search Console ever looks incomplete.
